Arquitectura C4 Nivel 2 (Contenedores) - Multi-Agente Bancario
Patrón Supervisor-Workers
1. Orquestador

CommercialSupervisor (LangGraph)

Implementa una máquina de estados finita construida sobre StateGraph. Administra el enrutamiento dinámico, invoca agentes especialistas en paralelo (Fan-Out) y sincroniza los resultados en el estado compartido antes de formular la respuesta final.

  • Enrutamiento condicional basado en intenciones
  • Gestión de contexto y memoria con Redis Checkpointer
  • Guardrails de seguridad (NeMo Guardrails / PII Masking)
2. Agentes de Dominio

Workers Especialistas

Cada sub-agente tiene un rol estricto con sus propias herramientas de ejecución. No intentan resolver todo; concentran su capacidad de razonamiento en una dimensión del problema comercial:

  • Client Intelligence: Perfil 360, saldos vivos y RAROC
  • Risk Underwriting: Rating y calibración Basilea IV
  • Pricing Engine: Cotización de margen y swaps de tipos
  • Compliance RAG: Normativa bancaria y límites de delegación
3. Protocolo Handoff

Traspaso de Estados Tipados

La comunicación entre agentes no es texto libre informal, sino contratos de datos estrictos en Pydantic / TypedDict. Esto previene alucinaciones y garantiza que las decisiones críticas contengan firmas verificables.

  • Esquemas Pydantic para entradas y salidas de herramientas
  • Trazabilidad completa con OpenTelemetry & LangSmith
  • Interrupción determinista para Human-In-The-Loop
Pipeline RAG Normativo & Consumo de APIs en Tiempo Real
Enterprise Tier 1

RAG Híbrido Estrategia de Recuperación Documental

Las políticas de riesgo y circulares normativas no pueden resumirse con pérdida de precisión. Se emplea una arquitectura en 4 fases:

1. Chunking Jerárquico: División por títulos y secciones normativas con preservación de tablas de límites financieros.
2. Búsqueda Híbrida: Dense Vector Search (BGE-Large) + Sparse BM25 para capturar cifras exactas (e.g., "1.000.000 €").
3. Reranker Neuronal: Cohere Rerank v3 para ordenar los 20 mejores pasajes a los 4 más relevantes antes del prompt.
4. Atribución Estricta: El modelo responde únicamente con citas directas al párrafo de la circular vigente.

APIs de Servicio Integración con Core Bancario & Tesorería

Los agentes ejecutan herramientas deterministas expuestas como APIs REST/gRPC autenticadas con OAuth2 mTLS:

GET /api/v1/crm/client/{cif}/profile: Devuelve la posición global, facturación auditada, historial de impagos y contratos activos.
POST /api/v2/risk/basel-iv/simulate: Ejecuta el modelo cuantitativo de probabilidad de default (PD) y pérdida en caso de impago (LGD).
GET /api/v1/treasury/curves/euribor-irs: Obtiene la curva interbancaria en tiempo real para cotización de swaps y spreads.
POST /api/v1/commercial/deals/draft: Crea el borrador de propuesta formal en el sistema de originación de créditos.
Implementación de LangGraph con TypedDict & Handoffs
Python 3.11+ / LangGraph 
from typing import Annotated, Sequence, TypedDict, Optional, List, Dict
import operator
from langchain_core.messages import BaseMessage, HumanMessage, AIMessage
from langgraph.graph import StateGraph, END

# 1. ESQUEMA DE ESTADO COMPARTIDO ENTRE AGENTES
class CommercialBotState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]
    client_cif: str
    client_360: Optional[Dict]
    risk_scoring: Optional[Dict]
    rag_citations: List[Dict]
    pricing_deal: Optional[Dict]
    requires_approval: bool
    approval_status: Optional[str]  # "PENDING" | "APPROVED" | "REJECTED"
    active_agent: str

# 2. DEFINICIÓN DEL NODO SUPERVISOR
def supervisor_node(state: CommercialBotState):
    """Evalúa la intención y decide qué agentes especialistas invocar"""
    last_message = state["messages"][-1].content
    # Lógica de enrutamiento basada en LLM estructurado
    return {
        "active_agent": "Supervisor",
        "client_cif": "A-48192034"
    }

# 3. SUB-AGENTE: RIESGOS BASILEA IV
def risk_underwriting_node(state: CommercialBotState):
    """Consulta la API de motor de riesgos y calcula PD/LGD"""
    cif = state["client_cif"]
    # Llamada a herramienta API interna de riesgos
    risk_data = {"rating": "A-", "pd": 0.0042, "lgd": 0.35, "max_limit_eur": 1500000}
    return {
        "risk_scoring": risk_data,
        "requires_approval": state.get("target_limit_eur", 1200000) > 1000000
    }

# 4. SUB-AGENTE: RAG NORMATIVO
def compliance_rag_node(state: CommercialBotState):
    """Recupera normativas vigentes sobre delegaciones de riesgo comercial"""
    citations = [
        {"doc": "Manual_Politicas_Credito_2026.pdf", "page": 42, "threshold_eur": 1000000}
    ]
    return {"rag_citations": citations}

# 5. CONSTRUCCIÓN DEL GRAFO EN LANGGRAPH
workflow = StateGraph(CommercialBotState)

workflow.add_node("supervisor", supervisor_node)
workflow.add_node("risk_agent", risk_underwriting_node)
workflow.add_node("compliance_rag", compliance_rag_node)

workflow.set_entry_point("supervisor")

# Bifurcación en paralelo hacia sub-agentes
workflow.add_edge("supervisor", "risk_agent")
workflow.add_edge("supervisor", "compliance_rag")

# Comprobación de Human-In-The-Loop antes de finalizar
def check_human_approval(state: CommercialBotState):
    if state.get("requires_approval") and state.get("approval_status") != "APPROVED":
        return "human_approval_checkpoint"
    return END

workflow.add_conditional_edges("risk_agent", check_human_approval, {
    "human_approval_checkpoint": END,
    END: END
})

app = workflow.compile()

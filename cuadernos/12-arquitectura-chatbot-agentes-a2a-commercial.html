Arquitectura del Chatbot de Commercial en Canales Web y App: Base de Conocimiento (RAG), Protocolo A2A y Agentes Operativos en Python

Visión Ejecutiva: Un Asistente Único en Web y App con «Dos Cerebros» (Conocimiento RAG + Operativa A2A en Python)

● ARQUITECTURA DE REFERENCIA · CANALES DIGITALES COMMERCIAL (WEB & APP)

Un único punto de contacto,
dos motores desacoplados: Base de Conocimiento y Flota de Agentes A2A

Cuando una empresa pregunta desde la App Móvil o el Portal Web por requisitos de un producto, normativa o tarifas, responde la Base de Conocimiento Híbrida (RAG) con citas verificadas. Cuando necesita información operativa en vivo (saldos, cobros SEPA, disponible en riesgo FEVE, anticipo de facturas o seguros de cambio), el Orquestador delega mediante el protocolo estándar A2A (Agent-to-Agent) en agentes especializados en Python que consultan las APIs del banco con el token de sesión del cliente.

💡 Por qué esta arquitectura convence tanto a Negocio como a Tecnología y Riesgos
  • Cero alucinaciones sobre datos operativos: El LLM nunca inventa un saldo ni calcula un tipo de interés a mano; los datos provienen de microservicios en Python (`FastAPI` + `Pydantic v2` + `httpx`) que consultan las APIs del Core con validación determinista.
  • Escalabilidad modular por dominios mediante A2A: Si mañana Commercial quiere incorporar un nuevo Agente de Avales Internacionales o un Agente de Leasing, el equipo técnico despliega un nuevo microservicio Python que publica su /.well-known/agent.json (Agent Card) y el Orquestador lo descubre automáticamente sin reescribir el chatbot.
  • Seguridad bancaria extremo a extremo (OAuth2 On-Behalf-Of + HITL): Ningún agente Python opera con permisos genéricos; propaga el token OBO del apoderado autenticado en Web/App y exige firma biométrica SCA (estado A2A input-required) antes de ejecutar cualquier contratación o disposición.

El Protocolo A2A (Agent-to-Agent) al Microscopio: Contratos JSON-RPC, Streaming SSE y Secuencia en Vivo

En una arquitectura empresarial moderna conviven dos estándares complementarios: MCP (Model Context Protocol) conecta a un agente con sus herramientas o fuentes de datos internas, mientras que A2A (Agent-to-Agent) permite que el Orquestador Central del Chatbot descubra y delegue tareas en Agentes Especialistas autónomos creados por distintos equipos en Python.
